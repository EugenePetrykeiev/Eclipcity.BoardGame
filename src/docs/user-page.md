# Eclipcity User Page Notes

The authenticated user page lives at:

```text
/user/{uuid}
```

The UUID is the existing `users.id` PostgreSQL primary key. It is generated by the backend with `uuid.uuid4`.

## Frontend Files

1. `src/pages/UserPage.jsx`
2. `src/styles/user-page.css`
3. `src/App.jsx`
4. `src/services/authClient.js`

`App.jsx` routes `/user/{uuid}` to `UserPage`. The page calls:

```text
GET /users/{uuid}
```

with credentials included. If the session cookie is missing or the route UUID does not match the authenticated user, the backend rejects the request.

## Backend Files

1. `src/backend/main.py`
2. `src/backend/models.py`
3. `src/backend/schemas.py`

The user UUID primary key already exists in `src/backend/models.py`:

```text
users.id UUID primary key
```

Auth responses now return a user page path:

```json
{
  "next": "/user/{uuid}"
}
```

Google OAuth callback also redirects to:

```text
{FRONTEND_BASE_URL}/user/{uuid}
```

## Page Content

The first version shows:

1. Local default avatar placeholder.
2. Username.
3. Placeholder match count.
4. Placeholder win count.
5. Action buttons:
   - Створити лоббі
   - Приєднатися до лоббі
   - Грати локально
   - Налаштування
   - Увімкнути/вимкнути звуки

The buttons are intentionally non-functional for now. Each button opens a toast notification.

## Avatar Placeholder

Until user avatar storage is added, the page always uses:

```text
src/assets/default-user-avatar.svg
```

Google `avatar_url` is intentionally ignored for now because external avatar loading is unreliable and the app does not yet have its own avatar storage.

## Toast Behavior

Toast notifications:

1. Appear in the top-right corner.
2. Slide in over `0.5s`.
3. Stay visible for about `5s`.
4. Fade and move upward before removal.
5. Show a close button in the top-right corner on hover or keyboard focus.
6. Expand vertically for longer text.
7. Do not scroll internally.

The visual style follows `context/cyberpunk-color-palette-spec.md`.
