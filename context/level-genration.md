# Специфікація генерації ігрового рівня

## 1. Призначення документа

Цей документ є джерелом вимог до компонування ігрового столу, генерації сітки, маршруту й тайлів.

Референсні зображення використовуються лише як приклади принципів компонування: безперервний ортогональний шлях, добре помітні фігури гравців і відокремлені службові зони. Візуальне оформлення референсів не копіюється.

## 2. Основні параметри

| Параметр | Значення |
|---|---:|
| Ширина столу | `100%` доступної ширини |
| Цільова висота столу | приблизно `900px` |
| Частка екрана | приблизно `90%` доступної площі |
| Розмір тайла | `60 × 60px` |
| Відстань між тайлами | `20px` |
| Крок сітки | `80px` (`60px` тайл + `20px` проміжок) |
| Кількість тайлів маршруту | `45`, без урахування виходу |
| Кількість типів тайлів | `9` |
| Повторів кожного типу | `5` |
| Ширина лінії шляху | `10px` |
| Довжина прямого сегмента | від `3` до `4` тайлів |
| Кут повороту | `90°` |
| Тестова сітка | видима лінія `1px` |
| Максимум гравців | `4` |

> Вихід є окремим кінцевим тайлом після 45 предметних тайлів. Це зберігає точний розподіл: 9 типів × 5 повторів = 45 предметних тайлів.

## 3. Компонування ігрового екрана

### 3.1. Ігровий стіл

- Ігровий стіл має бути єдиною основною рамкою ігрової сцени.
- Не допускаються вкладені декоративні рамки за схемою «рамка в рамці».
- Стіл займає `100%` доступної ширини контейнера та приблизно `90%` доступної площі екрана.
- Цільова висота на настільному екрані — близько `900px`.
- Якщо висота екрана менша, стіл використовує всю доступну висоту без перекриття основних елементів керування.
- Службові елементи, які накладаються на стіл, не повинні зменшувати його ширину або змінювати геометрію сітки.
- Після генерації маршрут разом із виходом центрується за власним фактичним bounding box відносно центру столу.
- Центрування виконується максимально точно по горизонталі та вертикалі. Якщо точний центр конфліктує із зарезервованою областю, обирається найближча до центру допустима позиція.

Орієнтовна модель розміру:

```css
.game-table {
  width: 100%;
  height: min(900px, calc(100dvh - var(--game-ui-reserve)));
}
```

### 3.2. Карти поточного гравця

- Рука поточного гравця розташовується по центру нижнього краю столу.
- Вертикальне зміщення задається значенням:

```css
bottom: clamp(-50px, -10vh, -20px);
```

- Карти не повинні змінювати розмір або позицію ігрового столу.
- Інтерактивна частина карт має залишатися доступною для наведення та натискання.
- Область руки є зарезервованою UI-зоною: тайли, вихід і лінія маршруту не можуть її перетинати.
- Між межею будь-якого тайла та видимою межею карт має залишатися щонайменше `10px`.

### 3.3. Панель інших гравців

- Панель розташовується поверх столу з лівого боку, починаючи від вертикального центру.
- Панель не резервує окрему ширину в макеті та не зменшує ігрове поле.
- Максимальна кількість комірок — `4`.
- Комірки розташовуються вертикальним стовпчиком.
- Кожна комірка має вертикальну орієнтацію та містить:
  - іконку гравця;
  - зображення сорочки карти;
  - кількість карт по центру сорочки.
- Нікнейм у комірці не показується.
- Панель повинна мати вищий шар за стіл і тайли.
- У заголовку розгорнутої лівої панелі поруч із назвою лобі показується секундомір гри у форматі `хв:сек`.
- Окремий таймер по центру верхньої частини екрана не показується.

### 3.4. Колода

- Колода є окремою інтерактивною сутністю.
- Вона розташовується з лівого боку столу, по вертикальному центру.
- Відстань від правого краю панелі інших гравців до колоди — `30px`.
- Підпис «Колода» не показується.
- Колода не може перекривати маршрут, вихід або стартову зону.

### 3.5. Стартова зона

- Стартова зона розташовується в нижньому лівому куті столу.
- Відступ від лівого та нижнього краю столу — `50px`.
- Зона має форму кола.
- У ній відображаються фігури гравців і кількість в’язнів.
- Для фігури використовується наявна SVG-маска гравця.
- Стартова зона не входить до маршруту тайлів і вважається зарезервованою областю.
- Перший тайл розташовується праворуч від стартового кола в найближчій доступній комірці сітки.
- Відстань між правим краєм стартового кола та лівим краєм першого тайла — щонайменше `10px`.
- Перший тайл має лише одного ортогонального сусіда маршруту — другий тайл. Інші частини маршруту не можуть оточувати або візуально перекривати його.

### 3.6. Керування ходом

- Блок із лічильником дій і кнопкою «Завершити хід» розташовується в нижній правій частині сцени.
- Блок притискається ближче до правого краю, щоб не перекривати маршрут.
- Відстань від блока керування до будь-якого тайла або виходу — щонайменше `10px`.

## 4. Сітка рівня

### 4.1. Геометрія

Сітка складається з окремого місця під тайл і окремого проміжку між тайлами:

```text
розмір тайла = 60px
проміжок = 20px
крок сітки = 60px + 20px = 80px
```

Кожен тайл займає одну логічну комірку `(column, row)`. Його координати обчислюються так:

```text
x = gridOffsetX + column × 80px
y = gridOffsetY + row × 80px
```

Завдяки цьому відстань між сусідніми тайлами по горизонталі та вертикалі завжди дорівнює `20px`.

### 4.2. Межі та зарезервовані області

Перед генерацією маршруту створюється маска недоступних комірок. До неї входять:

- панель інших гравців;
- колода та її безпечний відступ;
- стартова зона;
- внутрішній відступ від країв столу;
- постійні елементи керування, якщо вони розташовані всередині столу.
- область карт поточного гравця разом із безпечним відступом;
- блок завершення ходу разом із безпечним відступом.

Тайл повинен повністю вміщуватися в межі столу. Генерація тайла частково або повністю за межами столу заборонена.

Для тайлів зберігається окремий проміжок `20px`. Для перевірки зіткнень із UI використовується прямокутник UI-сутності, розширений на `10px`. Якщо тайл або вихід перетинає цей прямокутник, розташування вважається недопустимим.

Нижня частина маршруту підіймається на один крок сітки (`80px`) відносно початкового центрованого положення, якщо без цього тайли потрапляють у зону карт.

### 4.3. Тестовий режим

Під час тестування логічна сітка показується поверх фону столу лініями товщиною `1px`.

Сітка є діагностичним шаром:

- не перехоплює події курсора;
- знаходиться нижче тайлів, фігур та UI;
- може бути вимкнена одним прапорцем конфігурації перед релізом.

## 5. Тайли та вихід

- На маршруті розміщується рівно `45` предметних тайлів і один окремий тайл виходу.
- Використовується `9` типів тайлів, кожен тип трапляється рівно `5` разів.
- Усі звичайні тайли мають розмір `60 × 60px`.
- Вихід є повноцінним тайлом розміром `60 × 60px`.
- Вихід бере участь у наведенні, підсвічуванні, перевірці позиції та побудові шляху так само, як інші тайли.
- Вихід завжди є останньою точкою маршруту.
- Вихід не повинен торкатися колоди, стартової зони, панелі гравців, елементів керування або іншої сутності, яка не належить маршруту.

Після побудови геометрії маршруту типи тайлів перемішуються окремо. Набір для перемішування містить по п’ять екземплярів кожного з дев’яти типів.

Якщо залишається чинним наявне правило послідовності, генератор додатково не допускає трьох однакових типів поспіль і обмежує повторення однакової пари відповідно до правил гри.

## 6. Правила побудови маршруту

Маршрут є впорядкованим списком унікальних комірок сітки.

Обов’язкові умови:

1. Маршрут не перетинає сам себе.
2. Одна комірка не може використовуватися двічі.
3. Рух відбувається лише горизонтально або вертикально.
4. Кожен поворот має кут `90°`.
5. Один прямий сегмент містить щонайменше `3` і щонайбільше `4` тайли.
6. Кількість поворотів не обмежується.
7. Між усіма тайлами зберігається однаковий проміжок `20px`.
8. Лінія, яка візуально з’єднує центри сусідніх тайлів, має ширину `10px`.
9. Лінія проходить під тайлами та не виходить за межі маршруту.
10. Усі 45 тайлів повністю вміщуються в межі столу.
11. Остання комірка придатна для виходу та не контактує зі сторонніми сутностями.
12. Перший тайл розташований біля стартового кола та має лише одного сусіда маршруту.
13. Тайли, вихід і шлях не входять у розширені на `10px` області UI.
14. З’єднувальний сегмент від останнього предметного тайла до виходу не може перетинати, торкатися або проходити під будь-яким попереднім сегментом чи тайлом.
15. Вихід займає сусідню комірку сітки відносно останнього тайла та не прилягає ортогонально до жодного іншого тайла маршруту.

Перехрестя, T-подібні з’єднання, розгалуження та візуальне накладання незалежних частин шляху заборонені. Кожна внутрішня точка маршруту має рівно два маршрутні зв’язки: з попереднім і наступним тайлом. Перший тайл та вихід мають по одному зв’язку.

## 7. Алгоритм генерації

Рекомендований підхід — пошук із поверненням (`backtracking`) по дискретній сітці.

### 7.1. Підготовка

1. Визначити фактичний розмір столу.
2. Обчислити кількість колонок і рядків із кроком `80px`.
3. Прив’язати лівий край сітки до першої доступної позиції праворуч від стартового кола.
4. Позначити зарезервовані й небезпечні комірки.
5. Вибрати допустиму початкову комірку біля стартової зони, але без перетину з нею.

### 7.2. Побудова геометрії

```text
route = [startCell]
direction = random(horizontal or vertical)

while route.length < 45:
    segmentLength = random(3, 4)
    candidateCells = наступні комірки в поточному напрямку

    if segment перевищує потрібну довжину:
        скоротити його до загальної довжини 45

    if усі candidateCells:
        - знаходяться в межах сітки
        - не зарезервовані
        - ще не входять до route
        - не створюють перетину
        - не порушують безпечні відстані
    then:
        додати segment до route
        повернути ліворуч або праворуч на 90°
    else:
        повернутися до попереднього сегмента
        спробувати іншу довжину або напрямок

validate route.length == 45
validate route.last canBeExit
```

Скорочення останнього сегмента допускається лише тоді, коли після скорочення він усе ще містить щонайменше три тайли. Інакше генератор повертається до попереднього сегмента.

### 7.3. Резервний варіант

Якщо повністю випадкова генерація не забезпечує стабільний час побудови, допускається підготувати `6–7` валідованих шаблонів маршруту.

Для кожної нової гри генератор:

1. випадково обирає шаблон;
2. за можливості віддзеркалює його по горизонталі або вертикалі;
3. окремо перемішує типи тайлів;
4. повторно перевіряє межі та зарезервовані області.

Шаблон зберігає лише список координат комірок, а не абсолютні піксельні позиції.

### 7.4. Центрування згенерованого рівня

Центрування виконується після побудови маршруту та безпечного розташування виходу, але до перетворення координат сітки на пікселі.

```text
levelCells = routeCells + exitCell
levelBounds = boundingBox(levelCells)
boardCenter = (boardWidth / 2, boardHeight / 2)
levelCenter = center(levelBounds)
gridOffset = boardCenter - levelCenter × gridStep
```

Після зміщення генератор повторно перевіряє межі столу та зарезервовані UI-зони. Сам маршрут не масштабується і не деформується: змінюється лише спільне зміщення всіх тайлів, виходу та лінії шляху.

Похибка центрування для рівня, який повністю вміщується на столі без конфлікту із зарезервованими областями, повинна дорівнювати `0px` по обох осях.

## 8. Рекомендована структура даних

```ts
type GridCell = {
  column: number;
  row: number;
};

type GeneratedTile = {
  index: number;
  typeId: string;
  cell: GridCell;
  isExit: boolean;
};

type GeneratedLevel = {
  version: number;
  templateId?: string;
  tileSize: 60;
  gap: 20;
  pathWidth: 10;
  tiles: GeneratedTile[];
};
```

Абсолютні координати не зберігаються в даних рівня. Вони обчислюються з координат комірки, кроку сітки та зміщення сітки всередині столу.

## 9. Порядок шарів

Рекомендований порядок від нижнього до верхнього:

1. фон і єдина рамка столу;
2. тестова сітка `1px`;
3. лінія маршруту `10px`;
4. тайли та вихід;
5. фігури в’язнів;
6. колода і стартова зона;
7. карти поточного гравця;
8. панель інших гравців;
9. підказки, попапи та модальні елементи.

Фігура в’язня завжди має бути вище тайла, на якому вона стоїть. Підказки та попапи не можуть перекриватися тайлами.

## 10. Критерії приймання

- На екрані є лише одна рамка ігрового столу.
- Стіл використовує всю доступну ширину та має цільову висоту близько `900px`.
- Панель інших гравців накладається поверх столу й не зменшує його.
- На панелі відображається до чотирьох вертикальних комірок без нікнеймів.
- Колода розташована на `30px` правіше панелі та не має текстового підпису.
- Стартова зона має круглу форму та відступи `50px` зліва і знизу.
- Перший тайл знаходиться праворуч від стартового кола з проміжком щонайменше `10px`.
- Перший тайл має лише одного сусіда маршруту й не перекривається іншими тайлами.
- Згенеровано рівно 45 предметних тайлів і один тайл виходу.
- Кожен із дев’яти типів використано рівно п’ять разів.
- Кожен тайл і вихід мають розмір `60 × 60px`.
- Відстань між сусідніми тайлами всюди дорівнює `20px`.
- Прямі сегменти містять від трьох до чотирьох тайлів.
- Усі повороти прямокутні, шлях не перетинається.
- Вихід не торкається сторонніх сутностей.
- З’єднання з виходом не утворює перехрестя або T-подібного розгалуження з маршрутом.
- Жоден тайл не виходить за межі столу.
- Bounding box маршруту разом із виходом розташований максимально близько до геометричного центру столу.
- Жоден тайл, вихід або сегмент шляху не перетинає карти гравця чи елементи UI; мінімальний відступ — `10px`.
- Кнопка «Завершити хід» зміщена до правого краю і не перекриває маршрут.
- Таймер розташований у заголовку лівої панелі біля назви лобі; верхнього центрального таймера немає.
- У тестовому режимі видно сітку товщиною `1px`.
- Ширина з’єднувального шляху дорівнює `10px`.
- Карти гравця мають нижнє зміщення `clamp(-50px, -10vh, -20px)`.

## 11. Автоматичні перевірки генератора

Для кожного згенерованого рівня мають виконуватися перевірки:

```text
tiles.length === 45
countByType(typeId) === 5 для кожного з 9 типів
allCellsAreUnique === true
allTilesAreInsideBoard === true
allSegmentsHaveLengthBetween(3, 4) === true
allTurnsAre90Degrees === true
pathHasNoIntersections === true
pathHasNoBranches === true
gapBetweenTiles === 20px
exitIsLastTile === true
exitHasNoEntityCollision === true
exitConnectorHasNoIntersection === true
exitHasOnlyLastTileAsNeighbor === true
levelCenterErrorX === 0px
levelCenterErrorY === 0px
```

Для оцінки стабільності генератор потрібно прогнати щонайменше `1 000` разів. Кожен прогін повинен завершитися валідним рівнем або контрольовано перейти до одного з підготовлених шаблонів.

## 12. Тестовий endpoint генерації

Для діагностики використовується:

```http
GET /api/test/level-generation
```

Доступні query-параметри:

- `shape_id` — номер одного із семи шаблонів; якщо не передано, шаблон обирається випадково;
- `tile_count` — кількість предметних тайлів, стандартне значення `45`;
- `board_width` — ширина тестового столу в пікселях, стандартно `1920`;
- `board_height` — висота тестового столу в пікселях, стандартно `900`.

Приклад:

```http
GET /api/test/level-generation?shape_id=3&tile_count=45&board_width=1920&board_height=900
```

Endpoint повертає логічні координати тайлів, координату виходу, піксельний layout, межі рівня, похибку центрування та окремий результат кожної автоматичної перевірки. Поле `validation.valid` може бути `true` лише тоді, коли всі перевірки ТЗ успішні.
