# Eclipcity User Page Notes

The authenticated user page lives at:

```text
/user/{uuid}
```

The UUID is the existing `users.id` PostgreSQL primary key. It is generated by the backend with `uuid.uuid4`.

When an authenticated user opens the home route, the frontend checks:

```text
GET /auth/session
```

If the response is authenticated, the browser redirects to:

```text
/user/{uuid}
```

`/auth/session` returns `200` for both authenticated and anonymous visitors so
the home page can check session state without creating expected `401` console
noise.

## Frontend Files

1. `src/pages/UserPage.jsx`
2. `src/styles/user-page.css`
3. `src/App.jsx`
4. `src/services/authClient.js`

`App.jsx` routes `/user/{uuid}` to `UserPage`. The page calls:

```text
GET /users/{uuid}
```

with credentials included. If the session cookie is missing or the route UUID does not match the authenticated user, the backend rejects the request.

## Backend Files

1. `src/backend/main.py`
2. `src/backend/models.py`
3. `src/backend/schemas.py`

The user UUID primary key already exists in `src/backend/models.py`:

```text
users.id UUID primary key
```

Auth responses now return a user page path:

```json
{
  "next": "/user/{uuid}"
}
```

Google OAuth callback also redirects to:

```text
{FRONTEND_BASE_URL}/user/{uuid}
```

## Page Content

The first version shows:

1. Local default avatar placeholder.
2. Username.
3. Placeholder match count.
4. Placeholder win count.
5. Action buttons:
   - Почати гру
   - Налаштування
   - Увімкнути/вимкнути звуки

`Створити лоббі` now creates a persisted lobby through the backend. A lobby gets
a unique 5-character code and opens on:

```text
/lobby/{code}
```

The code is used for both public lobby rows and private direct joins.

## Lobby Persistence

Lobby data is stored in PostgreSQL with SQLAlchemy models in:

```text
src/backend/models.py
```

Tables:

```text
lobbies
- id UUID primary key
- code varchar(5), unique
- name varchar(15)
- max_players integer
- is_public boolean
- status varchar(16): waiting, closed
- created_by_user_id UUID references users(id)
- created_at timestamp
- updated_at timestamp

lobby_players
- lobby_id UUID references lobbies(id)
- user_id UUID references users(id)
- nickname varchar(24)
- team_color varchar(16)
- is_host boolean
- joined_at timestamp

lobby_events
- id UUID primary key
- lobby_id UUID references lobbies(id)
- event_type varchar(32)
- message text
- created_at timestamp
```

The app keeps empty lobbies as `closed` instead of physically deleting them. This
removes them from active/public lists while preserving the event log.

Apply the Alembic schema migrations from the repository root before starting the
backend:

```bash
alembic upgrade head
```

The backend never creates or alters tables during application startup. The local
Docker stack runs the same command in its one-shot `migration` service.

Implemented behavior:

1. `Почати гру` opens a centered game mode modal.
2. The modal contains `Створити гру`, `Приєднатися до гри`, and `Грати локально`.
3. After a game scenario is selected, the left menu button becomes inactive and
   changes its label according to the selected flow.
4. `Створити` opens a setup panel.
5. The player chooses max players from `2` to `5`.
6. The lobby can be public or private.
7. The lobby name is optional. Empty value becomes `Untitled lobby`.
8. Custom lobby names must be `3-15` characters and may contain letters, digits,
   spaces, and these symbols: `` !@#$%^&*(),./|\?`~ ``.
9. The backend generates a unique 5-character lobby code.
10. After creation, the host appears in the lobby table immediately.
11. The browser route changes to `/lobby/{code}`.
12. The lobby code is clickable and copies the 5-character ID to the clipboard.
13. Active lobby state refreshes with HTTP polling so the host sees newly joined
    players without manually refreshing the page.
14. `Приєднати` opens a public lobby list.
15. The public lobby header and code input stay at the top while the lobby rows
    scroll below.
16. The public list shows lobby name, lobby ID, and current/max players.
17. A row can be selected, then joined with `Приєднатися до лоббі`.
18. A lobby code can be entered directly with `Приєднатися за кодом`.
19. The host can kick other players with a hover-only `X` button at the right
    side of each player row.
20. The host checkbox is read-only.
21. The `Старт` button is only visible to the lobby host.
22. The player table reserves enough space for five players.
23. The event log records lobby creation, joins/leaves, kicks, team changes, and
    host changes.
24. The lobby event area is fixed to about six rows and scrolls internally.
25. The chat input is present but disabled.
26. `Старт` currently shows a toast notification.
27. `Покинути лоббі` removes the current player, returns the browser to
    `/user/{uuid}`, and clears the active lobby UI state. If the lobby becomes
    empty, the room is closed.
28. If the user opens `Налаштування` while a lobby is active, the lobby collapses
    into a bottom-right status popup with filled/empty player dots.
29. The bottom-right collapsed lobby popup keeps refreshing through the same
    active lobby polling.
30. Clicking the username in the left profile block opens `/user/{uuid}` and
    shows the temporary profile mock panel in the right area.

The backend never silently reuses an older active lobby during new lobby
creation. Before `POST /lobbies` creates a room, it removes the current user
from any active lobby memberships. If the user was the host, host ownership is
transferred to the next player; if the old room becomes empty, it is closed.
`POST /lobbies/{code}/join` applies the same cleanup for other active lobbies
before joining the requested room.

## Lobby API

Backend implementation files:

```text
src/backend/main.py
src/backend/lobby_repository.py
src/backend/models.py
src/backend/schemas.py
migrations/
```

Frontend implementation files:

```text
src/pages/UserPage.jsx
src/services/authClient.js
src/styles/user-page.css
src/App.jsx
src/i18n/I18nProvider.jsx
```

Endpoints:

```text
GET /auth/session
GET /lobbies/public
POST /lobbies
GET /lobbies/{lobby_code}
GET /lobby/{lobby_code}
POST /lobbies/{lobby_code}/join
PATCH /lobbies/{lobby_code}/players/me
POST /lobbies/{lobby_code}/leave
DELETE /lobbies/{lobby_code}/players/{player_user_id}
```

`POST /lobbies` body:

```json
{
  "name": "Run#7",
  "max_players": 5,
  "is_public": true
}
```

`PATCH /lobbies/{lobby_code}/players/me` body:

```json
{
  "team_color": "green"
}
```

Supported `team_color` values:

```text
green, purple, orange, pink, turquoise
```

The lobby response includes:

```json
{
  "code": "A1B2C",
  "path": "/lobby/A1B2C",
  "players": [],
  "events": [],
  "is_member": true,
  "is_host": true
}
```

## Frontend Lobby Flow

The user page supports two authenticated routes:

```text
/user/{uuid}
/lobby/{code}
```

Opening `/lobby/{code}` automatically calls `POST /lobbies/{code}/join` for the
current authenticated user. This makes direct private links work without a
separate landing screen.

The current version uses normal HTTP requests plus short polling for active
lobby refreshes. For lower-latency multi-user updates, the next backend step
should add WebSocket or Server-Sent Events for lobby membership, host transfer,
team changes, kicks, and event logs.

Scrollable lobby areas use the reusable `ScrollPanel` component in
`src/pages/UserPage.jsx`. The scrollbar is native but styled in
`src/styles/user-page.css`; it appears on hover/focus and fades back quickly.

## Language Switcher

The user page supports Ukrainian and English UI labels through:

```text
src/i18n/I18nProvider.jsx
```

Default language is Ukrainian. The selected language is stored in browser
`localStorage` under:

```text
eclipcity_language
```

The sidebar shows two language buttons below the sound toggle:

```text
УКР | EN
```

Switching language updates the UI immediately without a page reload. Lobby event
messages already stored in the database are not translated retroactively because
they are persisted as event text.

## Avatar Placeholder

Until user avatar storage is added, the page always uses:

```text
src/assets/default-user-avatar.svg
```

Google `avatar_url` is intentionally ignored for now because external avatar loading is unreliable and the app does not yet have its own avatar storage.

## Toast Behavior

Toast notifications:

1. Appear in the top-right corner.
2. Slide in over `0.5s`.
3. Stay visible for about `5s`.
4. Fade and move upward before removal.
5. Show a close button in the top-right corner on hover or keyboard focus.
6. Expand vertically for longer text.
7. Do not scroll internally.

The visual style follows `context/cyberpunk-color-palette-spec.md`.
